# Omnis AI 智能客服平台 - 产品优化方案 V1.1

> 版本：v1.1  
> 更新日期：2026-05-11  
> 文档类型：解决方案补充  
> 关联文档：Omnis 智能客服平台 - 产品设计文档 V1.0

---

## 1. 方案背景

V1.0 的“负反馈自学习”“人工接管”“RAG 问答”等模块已解决了“答得准、接得住、看得清”，但在上线后 3 个月左右的真实运营中，将暴露三个关键盲区：

- 知识管理员“不敢改，不会改”，导致负反馈闭环空转
- 转人工触发逻辑粗暴，忽视用户情绪，反而加剧投诉
- 定价和建模仍停留在“降本”，未体现“增收”价值，天花板偏低

同时，产品存在三个高杠杆的机会点：

- 从“问答客服”升级为“任务完成型客服”，实现业务闭环
- 行业知识库复用，把冷启动成本变成竞争壁垒
- 情绪识别能力弥补，让体验不只智能，更有温度

本方案针对上述问题，给出具体功能设计和实施路径。

---

## 2. 方案目标

- 把负反馈闭环的有效运转率从不足 30% 提升至 80% 以上
- 转人工后的用户满意度（CSAT）提升 15 个百分点
- 单客户生命周期价值（LTV）提升 2 倍（通过增收价值定价和任务闭环）
- 新客户冷启动时间缩短 60%

---

## 3. 功能优化设计

### 3.1 强化可干预性：负反馈修复工作台

#### 用户故事

作为知识管理员，当系统提示“12 条低分回答待审核”时，我可以在一屏内完成“诊断 → 修复 → 验证 → 发布”，不需要跳转 3 个页面、操作 5 次。系统还会告诉我先修哪个、怎么修、修完影响哪些问答。

#### 核心流程

```text
低分回答聚合 → 影响面排序 → 点击修复 → 沙箱编辑器 → 回归测试 → 一键发布
```

#### 关键交互

| 步骤 | 现有问题 | 优化方案 |
|:---|:---|:---|
| 1. 待修复列表 | 按时间倒序，无法判断优先级 | 影响面加权排序：按“触发次数 × 业务严重度（退款/投诉加权 1.5x）”计算紧急指数，强制置顶 |
| 2. 问题诊断 | 只展示检索和生成日志，靠人判断 | AI 自动下诊断标签：知识缺失 / 检索错误 / 生成错误，并给出 1 条推荐操作 |
| 3. 知识修复 | 跳到文档管理页，手动编辑 | 一键弹出修复面板：根据诊断类型预填内容（如知识缺失自动生成 FAQ 草稿），管理员只需修改确认 |
| 4. 效果验证 | 无，修改后两眼一抹黑 | 沙箱测试：左侧编辑，右侧实时用历史低分问题做回归测试，高亮前后差异 |
| 5. 发布与回滚 | 直接覆盖，无版本管理 | 知识版本管理：每次修复生成快照，支持 3 天内一键回滚，且展示回滚影响范围（哪些问题的答案会变回旧版） |

#### 成功指标

- 管理员首次修复平均耗时：从 15 分钟 → < 3 分钟
- 修复后同一知识点的低分率下降 > 60%
- 知识管理员月活跃操作频次（修复 + 新增）提升至上线前的 3 倍

### 3.2 转人工体验升级：置信度 + 情绪双模触发

#### 用户故事

作为终端用户，当我对 AI 回答不满意甚至生气时，我能立刻知道 AI 正在想办法、同时可以一键转人工，而不是被系统生硬地“判定”需要转接，转过去还要重新说一遍问题。

#### 核心流程

```text
对话中实时情绪识别 → 多信号融合 → 安抚 + 明确选择 → 无缝转接（带情绪标签）
```

#### 关键交互

| 场景 | 原逻辑 | 新逻辑 |
|:---|:---|:---|
| 第一次置信度 0.55 | 自动推荐转人工或直接兜底 | AI 输出：“这个问题我不太确定，以下是我能找到的最相关信息【展示引用】，如果不对，点这里转人工，我帮您把聊天记录发给客服。” |
| 用户连续输入两次“转人工”“听不懂” | 不识别情绪，继续按文本语义检索 | 即时识别负面情绪，触发安抚话术：“很抱歉，我这就帮您转接人工，您不用重复问题～”并高亮转接按钮 |
| 用户对某一回答点“踩” + 追问“还是不对” | 系统只记录点踩，不联动 | 立刻推送：“我好像没帮上忙，要现在转人工吗？客服可以看到我们的聊天记录，不会让您再解释一遍。” |

#### 人工工作台联动

- 转人工后，坐席工作台的摘要卡片显示“情绪标签”（如 😡 愤怒 / 😟 失望 / 😵 困惑），让客服第一时间调整沟通策略
- 同步传递“触发转接的上一条 AI 回答”，方便客服直接修正错误点

#### 成功指标

- 转人工后的用户 CSAT 提升 > 15%
- “重复说明问题”的坐席投诉量下降 50%
- 因情绪导致的客诉升级率降低 30%

### 3.3 从问答到任务：可执行卡片式交互

#### 用户故事

作为终端用户，当我问“怎么退货”“修改地址”时，我不只想看一篇文档，我想直接在那个对话里完成操作，至少能一键发起。

#### 核心流程

```text
用户意图识别为“可执行任务” → RAG 回答 + 可执行卡片 → 用户点击卡片 → 调业务接口 / 进入多轮表单 → 生成待确认工单 → 执行
```

#### 关键交互

示例：退货场景

| 步骤 | 界面表现 |
|:---|:---|
| 用户：“我要退货” | AI 回复：“好的，您的订单 #A10086（T恤白色M）还在退货期。要现在申请吗？”下方出现【开始退货申请】卡片 |
| 点击卡片 | 展开轻表单：“退货原因（选填）、是否已拆吊牌”等，进度条显示 2/3 步 |
| 提交 | AI：“已为您生成退货单，点击确认提交” → 用户点确认 → 后端创建工单 |
| 不可执行时 | 降级为普通 RAG 答案，但仍保留“转人工”捷径 |

#### 可执行任务类型（一期）

- 退货/换货申请
- 修改订单地址（未发货状态）
- 预约维修/上门
- 查询并续费课程
- 发起退款（结合业务系统）

#### 权限与安全

- 任务卡片调用业务接口，必须携带用户身份 token，所有操作写入审计日志
- 可执行卡片仅在私有化/混合部署的企业版开放，SaaS 版需额外对接确认

#### 成功指标

- 任务成功率（卡片发起 → 用户提交） > 60%
- 一次对话内完成业务闭环的比例 > 20%
- 因“AI 帮我直接办成事”产生的 NPS 推荐值比纯问答场景高出 20 分

### 3.4 情绪识别与主动服务

#### 功能要点

- 识别指标：重复提问（同一问题改写后问 2 次以上）、短句否定（“不对”“不行”）、攻击性语言、连续点踩
- 触发动作：自动插入安抚语句，同步在人工工作台标记情绪标签
- 与转人工联动：当情绪值 + 置信度双低，主动推送转人工

#### 盲区提醒

情绪识别模型可能误判（如口语化“不是吧”不代表生气），需结合上下文阈值，初期可保守设阈值，后期通过人工标注迭代。

### 3.5 定价模型升级：增收价值定价

#### 现有问题

仅按坐席数和 Token 量定价，将产品定位为“降本工具”，难以捕获其为客户带来的增量收入（如续费率提升、商机转化）。

#### 新增定价维度（企业版）

- 效果增值包：若客户启用“任务型卡片”和“主动推荐（课程/商品）”，可按 AI 促成的 GMV 或工单完成量收取 1% ~ 3% 的效果服务费
- 行业知识加速包：新客户可付费获取同行业预置知识库模板，缩短冷启动时间（详见 3.6）
- 保留原按坐席订阅费 + Token 的基础模式，增值部分为可选

#### 对销售端的影响

- 售前演示重点从“你们能省多少人”转变为“我们帮你们多赚多少钱”
- 所需协同：与客户业务系统对接、数据回传验证，需要 CSM/实施团队具备一定业务咨询能力

### 3.6 行业知识库复用与冷启动加速

#### 痛点

每个新客户都要从零构建知识库，尤其是中小客户，文档质量差、条目不全，导致初期效果不好，续费难。

#### 方案

在保障多租户数据隔离的前提下，建设“行业通用知识库层”。

- 抽取各行业高频通用知识（如电商退货规则框架、教育行业退费政策模板、SaaS 常见功能问答），脱敏后形成行业预置模板
- 新客户创建租户时，可选择“自动复制行业模板库 + 自定义合并”，再上传本企业特有文档，冷启动文档数量减少 60%
- 持续学习机制：客户新增的高质量知识，经脱敏同意后，可反哺行业库，形成飞轮

#### 相关配置

- 文档级 ACL 需扩展支持“行业库可见性”标签，确保不跨租户泄露
- 知识管理员在修复知识时，可勾选“贡献至行业通用库（匿名）”，作为增值服务的一项指标

## 4. 实施路线图

| 阶段 | 内容 | 预期时间 |
|:---|:---|:---|
| Phase 1 快速修补 | 1. 情绪识别 + 双模转人工<br>2. 负反馈修复工作台核心流程（诊断 + 一屏修复，先不做沙箱） | 6-8 周 |
| Phase 2 价值升级 | 1. 任务型卡片（一期 3 类任务）<br>2. 知识版本管理与沙箱测试<br>3. 行业知识库框架搭建 | 10-14 周 |
| Phase 3 商业放大 | 1. 增收定价模型上线<br>2. 行业库自学习闭环<br>3. 第三方任务卡片市场/开放平台 | 20 周+ |

## 5. 指标监控与验证

| 优化模块 | 核心指标 | 当前基线 | 目标值 |
|:---|:---|:---|:---|
| 可干预性 | 管理员月均修复次数 | 假设 <5 | >20 |
| 可干预性 | 修复后低分率下降幅度 | - | >60% |
| 转人工优化 | 转人工 CSAT | 假设 70% | 85%+ |
| 转人工优化 | 重复说明问题投诉量 | - | 下降 50% |
| 任务型卡片 | 任务发起率（可执行意图中） | 0% | 30%+ |
| 任务型卡片 | 任务成功率 | - | >60% |
| 情绪识别 | 情绪相关客诉升级率 | - | 下降 30% |
| 知识复用 | 新客户冷启动平均天数 | 假设 7 天 | <3 天 |
| 商业价值 | 平均合同金额（ACV） | 基准 | 提升 40%+ |

## 6. 风险与应对

| 风险 | 可能性 | 影响 | 应对 |
|:---|:---|:---|:---|
| 情绪识别误判率高，导致用户被打扰 | 中 | 增加负面体验 | 实施初期仅开放给付费企业版，并提供开关；阈值可调 |
| 任务型卡片调用业务系统失败率高 | 高 | 功能使用率低 | 与关键客户共建首个任务场景，打磨接口稳定性后再铺开 |
| 行业库贡献意愿低 | 中 | 无法形成飞轮 | 贡献知识的企业可获订阅折扣或功能赠送 |
| 增收定价模式被客户抵制 | 中 | 丢单 | 保留纯订阅版，增收模式作为可选项展示，先跑 POC 验证效果 |

---

本方案为 V1.0 的优化增强包，所有功能均向后兼容现有架构，不改变核心 RAG、ACL 等基础设计。下一步可进入详细功能规格（Functional Spec）和交互原型阶段。
