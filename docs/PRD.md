# Omnis 智能客服平台 - 产品需求文档 (PRD)

> 版本：v0.1 | 日期：2026-05-09 | 状态：草稿

---

## 1. 产品概述

### 1.1 产品定义

Omnis 是一款基于 RAG（检索增强生成）的智能客服平台，为企业提供统一的知识驱动对话服务。支持内部员工服务（IT/HR/行政）和外部客户服务（售前/售后），通过多租户架构实现企业级 SaaS 部署。

### 1.2 核心价值

- **统一知识引擎**：一次入库，多渠道复用，消除知识孤岛
- **RAG 增强回答**：基于企业私有知识库生成准确回答，降低幻觉率
- **多租户隔离**：企业间数据完全隔离，企业内支持业务线隔离
- **LLM 无关性**：支持云端 API 与私有化部署，灵活切换不绑定

### 1.3 目标用户

| 角色                  | 描述                         | 核心诉求               |
| --------------------- | ---------------------------- | ---------------------- |
| 终端用户（员工/客户） | 通过各渠道发起咨询的使用者   | 快速获得准确回答       |
| 知识管理员            | 维护知识库内容的运营人员     | 高效管理知识、监控质量 |
| 系统管理员            | 配置租户/权限/集成的管理人员 | 灵活配置、安全可控     |
| 开发者                | 通过 API 集成的第三方开发者  | 稳定 API、完善文档     |

### 2.2 核心模块详细设计

#### M1 - 知识管理模块

**功能描述**：负责企业知识的采集、处理、存储和维护。

| 功能点     | 描述                                                        | 优先级 |
| ---------- | ----------------------------------------------------------- | ------ |
| 文档导入   | 支持 PDF/Word/Excel/PPT/Markdown/TXT 上传，自动解析提取内容 | P0     |
| 网页抓取   | 输入 URL 自动抓取网页内容，支持定时同步                     | P1     |
| 数据源连接 | 对接 MySQL/PostgreSQL/ES 等数据库，定时同步结构化数据       | P1     |
| API 数据源 | 配置 REST API 作为数据源，支持定时拉取                      | P2     |
| 文档分片   | 智能分片策略（按段落/语义/固定长度），支持自定义分片规则    | P0     |
| 向量化     | 文档分片后自动向量化，支持自定义 Embedding 模型             | P0     |
| 知识分类   | 按业务线/主题/租户组织知识，支持标签和目录树                | P0     |
| 版本管理   | 知识文档版本控制，支持回滚                                  | P2     |
| 质量监控   | 知识命中率、未覆盖问题统计，辅助发现知识缺口                | P1     |
| 文档权限   | 文档级访问控制，支持公开/指定角色/指定用户三种权限模式      | P0     |
| 权限继承   | 知识库权限默认继承到文档，文档可单独覆盖                    | P0     |
| 权限审计   | 文档访问/修改/权限变更的操作审计日志                        | P1     |

**文档权限模型**：

```
知识库 (KnowledgeBase)
 │
 ├── 权限设置：默认访问策略（公开/仅成员/自定义）
 │
 ├── 文档 (Document)
 │    │
 │    ├── Visibility（可见性）
 │    │    ├── Public   ── 知识库内所有成员可访问
 │    │    ├── Internal ── 仅指定角色可访问
 │    │    └── Private  ── 仅指定用户/用户组可访问
 │    │
 │    ├── ACL（访问控制列表）
 │    │    ├── PrincipalType: User | UserGroup | Role
 │    │    ├── PrincipalId
 │    │    └── Permission: Read | Edit | Delete | Share | Admin
 │    │
 │    └── 继承规则
 │         ├── 默认继承知识库权限
 │         └── 文档级 ACL 可覆盖继承权限（更严格优先）
 │
 └── 分片 (Chunk)
      └── 权限从文档继承，不可单独设置
```

> **关键约束**：RAG 检索时必须在检索阶段注入用户权限上下文，确保用户只能检索到有权限的文档内容，而非检索后再过滤。

**文档处理流程**：

```
上传/抓取/同步
    │
    ▼
格式解析（PDF/Word/HTML/...）
    │
    ▼
内容清洗（去重/去噪/格式化）
    │
    ▼
智能分片（段落/语义/滑动窗口）
    │
    ▼
向量化（Embedding）
    │
    ▼
存储（向量库 + 原文库）
    │
    ▼
索引更新
```

#### M2 - RAG 引擎模块

**功能描述**：负责检索增强生成的核心推理流程。

| 功能点       | 描述                                                   | 优先级 |
| ------------ | ------------------------------------------------------ | ------ |
| 查询改写     | 对用户问题进行改写、扩展、分解，提升检索召回率         | P0     |
| 混合检索     | 向量检索 + 关键词检索（BM25）融合，支持权重可配        | P0     |
| 重排序       | 对检索结果进行 Rerank，提升相关性排序                  | P1     |
| 答案生成     | 基于检索上下文，调用 LLM 生成结构化回答                | P0     |
| 引用溯源     | 回答中标注来源文档/段落，支持跳转查看原文              | P0     |
| 多轮上下文   | 结合对话历史进行检索和生成，维持多轮语义连贯           | P0     |
| 未命中兜底   | 检索无结果时触发兜底策略（转人工/提示无答案/推荐相关） | P1     |
| 知识边界     | 可配置是否允许 LLM 使用自身知识回答，还是仅限知识库    | P0     |
| 权限过滤检索 | 检索阶段注入用户权限上下文，仅召回有权文档的分片       | P0     |

**RAG 推理流程**：

```
用户提问
    │
    ▼
查询改写（Query Rewriting）
    │
    ├── 问题分解（Multi-Query）
    │
    ▼
混合检索（Hybrid Search）
    │
    ├── 注入用户权限上下文（可访问的文档/知识库列表）
    ├── 向量检索（语义相似度 Top-K，带权限过滤）
    ├── 关键词检索（BM25 Top-K，带权限过滤）
    │
    ▼
结果融合 + 重排序（Rerank）
    │
    ▼
上下文组装（Prompt Engineering）
    │
    ├── 系统提示词（角色/规则/约束）
    ├── 检索结果（Top-N 文档片段）
    ├── 对话历史（近 N 轮）
    │
    ▼
LLM 生成回答
    │
    ▼
后处理（引用标注/格式化/敏感词过滤）
    │
    ▼
返回给用户
```

```
    │       │       │       │

    │       │       │
    │       │       └── 成员管理（Member）

```

| 功能点   | 描述                                            | 优先级 |
| -------- | ----------------------------------------------- | ------ |
| 租户管理 | 租户注册/审核/启停，租户信息管理                | P0     |
| 数据隔离 | 租户间数据完全隔离（数据库/向量库/文件存储）    | P0     |

| 成员管理 | 租户/空间级别的成员邀请、角色分配               | P0     |
| 权限模型 | RBAC 权限模型，预置角色（管理员/编辑者/查看者） | P0     |

| 计费管理 | 按 Token 消耗/API 调用/存储量计费               | P2     |

## 3. 非功能需求

### 3.1 性能要求

| 指标                 | 目标值               |
| -------------------- | -------------------- |
| 首次响应时间（TTFT） | < 1s（流式首 Token） |
| RAG 检索延迟         | < 200ms（P95）       |
| 端到端回答延迟       | < 5s（含 LLM 生成）  |
| 并发会话数           | ≥ 1000 / 租户        |
| 向量检索 QPS         | ≥ 5000               |
| 系统可用性           | ≥ 99.9%              |

### 3.2 安全要求

| 要求     | 描述                                            |
| -------- | ----------------------------------------------- |
| 数据加密 | 传输层 TLS 1.2+，存储层 AES-256                 |
| 访问控制 | OAuth 2.0 / OIDC 认证，RBAC 授权                |
| 文档权限 | 文档级 ACL，检索阶段强制权限过滤，防止越权访问  |
| 数据隔离 | 租户级数据库/Schema 隔离，向量库命名空间隔离    |
| 审计日志 | 关键操作全量审计，日志保留 ≥ 180 天             |
| 敏感信息 | 对话中自动检测并脱敏敏感信息（手机号/身份证等） |
| 内容安全 | LLM 输出内容安全过滤，防止有害内容输出          |

### 3.3 可扩展性

- 微服务架构，各模块独立扩缩容
- 向量数据库支持水平扩展
- LLM 网关支持动态添加模型
- 渠道接入采用插件机制，便于扩展新渠道
