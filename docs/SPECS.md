## 2. 产品概述

### 2.1 产品定义

Omnis 是一款基于 RAG（Retrieval-Augmented Generation）的企业级智能客服平台，通过「可观测的知识问答 + 人机无缝协同 + 负反馈自学习」，帮助企业搭建可溯源、可控权、可迭代的 AI 客服能力。

### 2.2 核心价值

| 价值 | 规格化目标 |
|:---|:---|
| 答得准 | 使用混合检索、查询改写、知识边界和置信度评分降低幻觉 |
| 看得清 | 每条回答必须返回引用来源，支持悬停预览和跳转原文 |
| 接得住 | 低置信度、用户要求或负面情绪触发转人工，转接时携带摘要和上下文 |
| 学得快 | 点踩、低分回答、未命中和人工最终回复进入待审核/知识缺口流程 |
| 守得住 | 文档级 ACL 必须在检索阶段生效，禁止检索后应用层过滤 |
| 可运营 | 管理后台提供 RAG 调试、低置信度会话、未命中聚类和知识修复入口 |

### 2.3 目标角色

| 角色 | 核心任务 | 关键权限/视图 |
|:---|:---|:---|
| 终端用户 | 发起咨询、查看回答、评价、转人工、执行任务卡片 | 对话窗口、引用查看、评价按钮、任务卡片 |
| 一线坐席 | 接管会话、查看摘要、回复用户、采纳 AI 推荐 | 人工工作台、会话摘要、知识推荐、快捷回复 |
| 知识管理员 | 导入文档、配置权限、查看 RAG 调试、修复知识 | 知识库、文档 ACL、观测面板、修复工作台 |
| 系统管理员 | 配置租户、业务空间、成员、模型、渠道 | 租户后台、成员管理、LLM 网关、渠道配置 |
| 质检/合规官 | 审计高危对话、导出证据包、检查引用链 | 审计日志、证据包、敏感内容告警 |
| 开发者 | 通过 API/SDK 接入对话和知识能力 | REST API、Webhook、鉴权、接口日志 |

## 3. 版本范围

### 3.1 MVP v0.1 范围

MVP 目标是交付「单租户/单企业可用的 RAG 智能客服闭环」，覆盖 Web Widget、REST API、知识入库、RAG 问答、引用溯源、权限过滤、观测调试、负反馈待审核和单队列转人工摘要。

| 模块 | MVP 能力 | 优先级 |
|:---|:---|:---|
| 知识管理 | PDF/TXT/Markdown 上传、解析、分片、向量化、基础分类 | P0 |
| 文档权限 | 文档级 ACL、权限继承、检索阶段强制权限过滤 | P0 |
| RAG 引擎 | 查询改写、混合检索、答案生成、引用溯源、多轮上下文 | P0 |
| RAG 观测 | 记录检索结果、Prompt、LLM 原始输出、最终答案、置信度 | P0 |
| 对话引擎 | 会话创建、流式响应、历史记录、用户评价 | P0 |
| 转人工 | 用户主动转接、低置信度转接建议、自动摘要、单一队列 | P0 |
| 负反馈闭环 | 点踩进入待审核池，低分会话关联 RAG 日志 | P0 |
| 渠道 | Web Widget、REST API | P0 |
| LLM 网关 | OpenAI/Azure OpenAI 模型配置、模型调用日志、基础熔断 | P0 |
| 管理后台 | 知识库管理、对话详情、RAG 调试、系统配置 | P0 |

### 3.2 MVP 不包含

- 微信、企业微信、钉钉、飞书等 IM 渠道
- 复杂人工技能组路由、排班、工单 SLA
- 知识图谱、网页抓取、数据库数据源、API 数据源
- 完整多租户计费系统和效果增值计费
- 实时语音质检
- 复杂槽位填充任务流
- 第三方任务卡片市场

## 4. 总体架构规格

```text
-----------------------------------------------------------+
| 触达层：Web Widget | 独立页面 | REST API | Webhook        |
+-----------------------------------------------------------+
| 对话层：会话管理 | 多轮上下文 | 流式响应 | 转人工摘要       |
+-----------------------------------------------------------+
| RAG 层：查询改写 | 混合检索 | 重排序 | 答案生成 | 引用溯源 |
+-----------------------------------------------------------+
| 观测层：RAG 日志 | 置信度 | 未命中 | 反馈闭环 | 调试面板 |
+-----------------------------------------------------------+
| 知识层：文档解析 | 分片 | 向量化 | 分类 | 文档 ACL          |
+-----------------------------------------------------------+
| LLM 网关：模型配置 | 路由 | 熔断 | Token 统计 | 审计       |
+-----------------------------------------------------------+
| 平台层：租户 | Workspace | RBAC | 审计 | 监控 | 配额       |
+-----------------------------------------------------------+
```

### 4.2 推荐技术栈

| 层级 | 技术 | 说明 |
|:---|:---|:---|
| 后端 | .NET 9 / ASP.NET Core | 主业务服务 |
| API 网关 | YARP | 反向代理、鉴权、限流 |
| 前端 | Vue 3 + TypeScript | 管理后台和 Web Widget |
| 业务数据库 | PostgreSQL | 租户、知识、会话、审计 |

| 可观测 | Prometheus + Grafana + Serilog/ELK | 指标、日志、链路追踪 |

## 5. 核心业务流程

### 5.1 知识入库流程

```text
上传文档
  -> 校验文件类型/大小/权限
  -> 存储原始文件
  -> 解析文本
  -> 清洗去噪
  -> 分片
  -> 生成 Embedding
  -> 写入向量库和全文索引
  -> 更新文档状态
  -> 记录审计日志
```

验收要求：

- 支持 PDF、TXT、Markdown 三类 MVP 文件格式。
- 文档处理失败时，文档状态必须显示失败原因，允许重试。
- 每个 Chunk 必须包含 `tenant_id`、`workspace_id`、`knowledge_base_id`、`document_id`、`acl_hash` 等过滤字段。
- 文档 ACL 变更后，相关 Chunk 的检索过滤元数据必须同步更新。

### 5.2 RAG 问答流程

```text
用户提问
  -> 加载会话上下文
  -> 查询改写
  -> 注入身份与权限上下文
  -> 向量检索 + BM25 检索
  -> 结果融合与重排序
  -> 置信度初算
  -> 组装 Prompt
  -> 调用 LLM 流式生成
  -> 引用校验与敏感内容过滤
  -> 返回答案、引用、置信度
  -> 异步写入 RAG 观测日志
```

验收要求：

- 检索阶段必须携带权限过滤条件，禁止先召回再过滤。
- 当 Top 1 相似度低于阈值（默认 0.5）时，必须进入知识边界兜底，不允许编造答案。
- 回答必须包含结构化 `citations`，前端可展示引用编号、原文片段和跳转链接。
- RAG 观测写入失败不得阻断用户回答链路，但必须记录系统告警。

### 5.3 转人工流程

触发条件：

- 用户显式输入「转人工」「人工客服」「客服」等意图。
- 答案置信度低于阈值（默认 0.6），系统推荐转人工。
- 用户连续点踩或连续否定回答。
- v1.1 起，情绪分与置信度双低触发主动转人工。

MVP 流程：

```text
触发转人工
  -> 生成会话摘要
  -> 附带最近 10 轮消息
  -> 附带触发转接的 AI 回答与引用
  -> 创建人工接管记录
  -> 进入单一人工队列
  -> 坐席接入后 AI 暂停自动回复
```

验收要求：

- 转人工摘要必须包含用户意图、已确认信息、未解决问题、推荐话术。
- 坐席接入后，用户不需要重复描述核心问题。
- AI 在人工接入后默认静默，仅作为坐席侧推荐，不直接向用户发送消息。

### 5.4 负反馈闭环

MVP 流程：

```text
用户点踩/低分
  -> 记录反馈
  -> 关联 message、conversation、rag_inference_log
  -> 进入待审核池
  -> 知识管理员查看问题、答案、检索片段、Prompt
  -> 标记原因：知识缺失/检索错误/生成错误/权限问题/其他
  -> 创建知识修复任务
```

v1.1 扩展：

- 影响面排序：触发次数 × 业务严重度。
- AI 诊断标签：知识缺失、检索错误、生成错误。
- 沙箱编辑器：用历史低分问题做回归测试。
- 一键发布与版本回滚。

### 5.5 任务卡片流程（v1.1）

适用意图：

- 退货/换货申请
- 修改订单地址
- 预约维修/上门
- 查询并续费课程
- 发起退款

流程：

```text
识别可执行意图
  -> RAG 回答解释规则
  -> 返回任务卡片 schema
  -> 用户填写/确认
  -> 调业务接口
  -> 生成工单或执行结果
  -> 写入审计日志
```

约束：

- 任务接口必须携带用户身份 token。
- 高风险操作必须二次确认。
- 业务接口失败时降级为人工接管或普通 RAG 指引。

## 12. 验收清单

### 12.1 MVP 验收场景

1. 知识管理员上传 Markdown 文档，系统完成解析、分片、向量化，并可在文档详情查看分片。
2. 终端用户提问命中文档内容，AI 返回带引用的答案，点击引用可定位到原文。
3. 无权限用户提问敏感文档相关内容，检索结果、Prompt、答案和引用中均不得出现敏感文档信息。
4. 用户提问知识库未覆盖问题，系统明确说明未找到答案，并展示转人工入口。
5. 用户点踩回答后，知识管理员可在待审核池看到问题、AI 回答、检索片段和 Prompt。
6. 管理员在对话详情打开 RAG 调试面板，可查看完整链路。
7. 用户触发转人工后，坐席工作台展示摘要和最近 10 轮对话。
8. LLM 调用失败时，系统不崩溃，按配置降级到备用模型或转人工。
9. 文档 ACL 修改后，重新提问可立即或在配置时限内体现新权限。
10. 审计日志可追踪文档上传、权限修改、模型配置和证据导出。

### 12.2 权限专项验收

- 同一租户内，不同 Workspace 的用户不得检索彼此知识。
- 同一 Workspace 内，无 ACL 权限的用户不得检索 Private 文档。
- DenyUsers 优先级高于 AllowGroups。
- 检索日志中的 retrieved_chunks 不得包含无权限 Chunk。
- 引用跳转接口也必须校验文档读取权限。

### 12.3 RAG 质量验收

- Top 1 相似度低于阈值时不生成编造答案。
- 引用 ID 必须对应真实 Chunk，不允许 LLM 生成不存在的引用。
- Prompt 中的上下文必须来自检索阶段授权结果。
- 置信度低于 0.6 时必须出现转人工建议。

## 13. 风险与约束

| 风险 | 影响 | 应对 |
|:---|:---|:---|
| 权限过滤放在应用层 | 可能泄露敏感文档存在性 | 强制在向量库/搜索引擎查询阶段过滤 |
| 低质量文档导致回答错误 | 用户不信任系统 | RAG 观测、低分反馈、知识缺口报告 |
| LLM 输出引用不一致 | 溯源失真 | 后处理校验引用 ID，不存在则降级或重试 |
| 转人工摘要不准确 | 坐席误判问题 | 摘要必须附原始上下文和触发消息 |
| 情绪识别误判 | 打扰用户 | v1.1 初期仅作为提示，阈值可配置 |
| 任务卡片接口失败 | 业务闭环中断 | 降级为人工接管，所有调用写审计 |
